Factory Inventory Management

Architecture overview. A Vue 3 single-page app talks to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Architecture Tech stack Data flow API surface Frontend structure Observations

System architecture

Two processes on localhost, connected by plain HTTP and JSON.

The browser loads the SPA from Vite on port 3000. API calls go cross-origin to port 8001, so the server enables CORS for all origins.

Tech stack

Deliberately small. Three runtime dependencies on each side.

Frontend

  • Vue 3 ^3.4 with the Composition API
  • Vue Router ^4.3
  • Axios ^1.6 for HTTP
  • Vite ^8 dev server and build
  • Custom SVG charts, CSS Grid layouts
  • English and Japanese via a custom i18n composable

Backend

  • Python >=3.11
  • FastAPI >=0.110
  • Uvicorn ASGI server
  • Pydantic >=2.5 response models
  • uv for environments and dependencies

Data and tooling

  • JSON files in server/data/, no database
  • generate_data.py regenerates sample data
  • pytest, httpx, FastAPI TestClient for backend tests
  • scripts/start.sh and stop.sh manage both servers
  • No frontend tests

Data flow

How a filter change in the UI becomes a re-rendered view.

Request lifecycle

  1. User changes a filterFilterBar writes to shared refs in useFilters: period, warehouse, category, order status.
  2. The view reactsEach view sets up a watch on the filters it cares about and calls its load function when they change.
  3. api.js builds the requestgetCurrentFilters() returns the active values. Any filter equal to "all" is omitted from the query string.
  4. FastAPI filters in memoryThe handler runs apply_filters and filter_by_month over the Python lists loaded at startup.
  5. Pydantic validates the responseThe response_model checks and serializes the result to JSON.
  6. The view derives what it displaysRaw data lands in refs (allOrders, inventoryItems). Computed properties produce totals, chart series, and tables.

Which filters each endpoint honors

EndpointPeriodWarehouseCategoryStatus
/api/dashboard/summaryyesyesyesyes
/api/ordersyesyesyesyes
/api/inventorynoyesyesno
/api/demand, /api/backlognononono
/api/spending/*nononono

Inventory has no time dimension, so period is not applicable. Demand, backlog, and spending endpoints take no parameters. Views that need filtered data there combine them with filtered inventory or order calls.

Read-only by design

The server never writes to disk. Restarting it resets all data to the contents of the JSON files.

Observations

Things worth knowing before changing the code. Each was found by reading the source.

FindingDetail
Missing endpoints api.js calls /api/tasks (list, create, delete, toggle) and /api/purchase-orders, but main.py defines none of them. Task and purchase-order actions in the UI will fail against this backend. The PurchaseOrder models exist and purchase_orders.json is an empty list.
Unrouted view views/Backlog.vue is not registered in the router and is not imported anywhere. Backlog data reaches the UI through the Dashboard instead.
Hardcoded URL The API base URL http://localhost:8001 is a literal in api.js and again in Reports.vue, which calls axios directly and bypasses api.js.
Open CORS allow_origins=["*"] with credentials enabled. Fine for a local demo, not for deployment.
Duplicated logic Quarter-to-month mapping appears in both QUARTER_MAP and the if/elif chain inside get_quarterly_reports.
Test coverage Backend tests cover inventory, dashboard, and miscellaneous endpoints. The frontend has no tests.
